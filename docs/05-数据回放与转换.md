# 05-数据回放与转换

本文介绍 Zarr 数据的检查、机械臂回放以及向 LeRobot 数据集的转换。

## 数据回放

### 回放流程

`scripts/data/replay_zarr.py` 的主要执行顺序如下：

1. 以只读方式打开 Zarr 数据集，根据 `data/episode` 中连续的 episode 编号划分片段。
2. 检查必需数组、样本数量、位姿维度和数值有效性，并检查动作与位姿变化是否大致一致。
3. 列出可用 episode，等待操作者选择。此时尚未连接机械臂。
4. 选择后连接机械臂；确认回放后，机械臂先回到初始位置，再移动到该 episode 记录的开局位姿。
5. 使用所选 episode 的夹爪范围和 `gripper_mode`，按顺序发送记录的末端位移动作与夹爪动作。二值模式按阈值映射为 `0/1`；连续模式按记录的归一化值回放。结束、按 `q` 或中断后，可选择复位继续或退出。

检查发现动作和位姿变化不一致时，脚本会给出警告但仍允许选择回放；缺少必需数组、数据为空、数组长度不一致或位姿维度错误时则不能正常回放。`meta/episode_ends` 只用于显示元数据，episode 范围以 `data/episode` 为准。

### 使用方法

在仓库根目录运行：

```powershell
python scripts/data/replay_zarr.py --input datasets/demo.zarr --addr 192.168.31.232
```

可选参数：

- `--input`：Zarr 数据集路径。
- `--addr`：xArm 地址。
- `--hz`：回放频率，默认 `10`。机械臂接口调用耗时可能使实际频率低于设定值。
- `--speed`：机械臂运动速度参数，默认 `100`，有效范围为 `(0, 2000]`。

在 episode 列表中输入序号选择片段，输入 `q` 退出。开始运动前脚本会显示计算出的开局位姿并要求确认。运行前应确认机械臂周围空间、工装和速度设置适合这段轨迹，并确保急停可用。回放期间输入 `q` 会尝试停止机械臂。

#### 回放夹爪接口

- 从 `meta/episode_config/episode_XXXXXX.attrs["gripper_range"]` 读取原始范围 `[MIN, MAX]`；缺失或无效时跳过该 episode。
- 范围必须为两个整数，满足 `0 <= MIN < MAX <= 840`；首次创建 Env 时传入，切换 episode 时更新。
- 从同一 episode 的 `gripper_mode` attribute 读取 `binary` 或 `continuous`，开始确认前会打印回放模式。若旧 episode 缺少该 attribute，会警告并按二值模式回放；无效值会跳过该 episode。
- `binary` 模式将 `data/gripper_action` 的 `<=0.5` 转为 `0`、`>0.5` 转为 `1`；`continuous` 模式直接使用记录的归一化值，不做阈值化。首次或值变化时发送，相同值传 `None`。
- 初始化和回放前复位使用闭合指令 `0`；开始确认前显示本轮原始范围与模式。
- Zarr 转换到 LeRobot 时，选择相应 state/action 组合后，夹爪数值会保留为浮点数，但不复制 `gripper_mode`、`gripper_range` 或原始值数组。`verify_lerobot.py` 将夹爪作为普通 state/action 维度进行统计，不单独统计开合端点。

### 开局扰动与回放位姿

采集器在每个 episode 开始前复位到固定 Home 位姿，再施加该轮实际使用的固定与随机偏移。实际偏移保存在 `meta/episode_config/episode_XXXXXX` 的 `start_bias` 属性中。

回放时，脚本读取所选 episode 的 `start_bias`，复位到 Home 后直接发送这条偏置移动，再按顺序执行该 episode 的动作和夹爪记录。随机偏移不重新抽取，也不会重复叠加固定偏移。偏置是相对 Home 的六维增量 `[x, y, z, roll, pitch, yaw]`，不是绝对目标位姿。

当前回放要求所选 episode 存在有效的偏置元数据；缺失配置时会提示错误并跳过该 episode，不会使用首帧数据推算或回退到旧的开局移动方式。`data/pos` 仍保存每帧动作执行后的 `goal_pos`，用于数据检查；它不再决定回放前的偏置移动。

### 数据结构要点

每个样本必须包含以下数组，且第一维长度一致：

| 数组 | 含义 | 形状要求 |
| --- | --- | --- |
| `data/episode` | 每个样本所属的 episode 编号 | `(N,)` |
| `data/action` | 末端增量动作 | `(N, 6)` |
| `data/pos` | 动作后的目标位姿 | `(N, 6)` |
| `data/gripper_state` | 夹爪状态，二值 `0/1` 或连续归一化值 `0～1` | `(N, 1)` |
| `data/gripper_action` | 夹爪目标动作，二值 `0/1` 或连续归一化值 `0～1` | `(N, 1)` |
| `data/gripper_raw_position` | SDK 原始夹爪反馈位置 | `(N, 1)` |
| `data/gripper_raw_action` | 映射后的 SDK 原始夹爪目标位置 | `(N, 1)` |

如果数据集包含其他数组，它们也应与样本总数对齐。回放脚本以只读模式打开数据集，不会修复或改写数据。

启用 CoinFT 采集时，数据集还包含 `data/coinft_left` 和 `data/coinft_right` 两个逐帧字段，分别保存左、右传感器的六轴力/力矩，形状均为 `(N, 6)`、类型为 `float32`。这两路字段与 XArm 内置 FT 的 `data/force` 相互独立。采集用法见[遥操作与数据采集](04-遥操作与数据采集.md)，传感器接口和校准细节见 [CoinFT 接收代码说明](../xarm_toolkit/sensors/coinft/README.md)。

#### Force 按需记录与缺失数据回退

机械臂力传感器由采集入口的 `--force` 参数启用，默认关闭。Collector 根据 `env.use_force` 决定是否记录力数据：

| 采集配置 | 新建数据集的行为 |
| --- | --- |
| 不传 `--force` | 不创建 `data/force`，不缓存或写入力数据 |
| 传入 `--force` | 创建 `data/force`，每步记录六维力/力矩，形状为 `(N, 6)`，类型为 `float32` |

启用示例：

```powershell
python -m scripts.data.collect_data --force --dataset datasets/with_force.zarr
```

启用 force 后，如果某步观察值 `obs["ext_force"]` 为 `None`，仍沿用补零回退：本步记录六维零值，并立即输出 `WARNING`，包含 episode 编号、从 1 开始的步数及补零说明。采集继续执行，不跳过该步，以保持各数组长度一致。每个触发回退的步骤都会记录警告；该处理仅针对读数为 `None`，不捕获或屏蔽 Env 抛出的异常。

补零记录与真实六维零读数在 `data/force` 中没有单独的区分标记，需要结合运行日志判断。开启 `--debug` 时，逐步日志始终包含 `force_enabled`，仅在启用 force 时包含六维 `force` 数值；回退步骤显示的是补零后的值，回退警告不依赖 `--debug`。

续采要求 `--force` 开关与已有数据集的 `data/force` 字段保持一致：有该字段则必须启用 force，没有该字段则必须关闭 force。不一致时 Collector 在打开数据集后抛出错误，不开始追加采集数据，也不会删除已有字段或补写历史数据。旧版本即使未启用 force 也会创建该字段，因此旧数据集仍按字段实际存在情况检查；如需关闭 force 采集，应使用没有该字段的数据集或新建数据集。

#### Episode 级采集配置

采集器会把每个**成功保存**的 episode 的开局偏置配置写入 Zarr 根目录下的 `meta/episode_config/`。例如：

```text
demo.zarr/
└── meta/
    ├── episode_ends
    └── episode_config/
        ├── episode_000000/
        └── episode_000001/
```

每个 `episode_XXXXXX` 是一个 Zarr group，具体配置保存在该 group 的 attributes 中，而不是逐帧数组：

| Attribute | 含义 |
| --- | --- |
| `episode_index` | episode 的实际编号；目录名补齐为 6 位只是为了便于排序 |
| `start_bias` | 本轮实际应用的开局偏移 `[x, y, z, roll, pitch, yaw]`，包含随机抽样结果 |
| `start_bias_base` | 配置的固定平移偏置 `[x, y, z]` |
| `random_bias_ranges` | 本轮配置的随机偏移范围，例如 `{"x": [-50, 70]}`；未配置的轴不出现 |
| `gripper_always_closed` | 本轮是否启用了夹爪始终记为闭合的记录配置 |
| `gripper_mode` | 本轮夹爪控制和记录模式：`binary` 或 `continuous` |
| `gripper_range` | 本轮原始闭合、张开位置，两个整数的列表 `[MIN, MAX]`；来自 `--gripper-range`，默认 `[0, 840]`，Collector 仅保存配置 |

例如，固定偏置为 `[0, 0, -200]`，X 轴范围为 `[-50, 70]`，本轮抽到 `+35` 时，`start_bias` 会记录 `[35, 0, -200, 0, 0, 0]`，同时 `start_bias_base` 记录 `[0, 0, -200]`，随机范围单独保存在 `random_bias_ranges` 中。

配置只在 episode 数据确认保存后写入；被丢弃的 episode 不会留下配置组。旧数据集或断点续采前已有的 episode 可能没有对应配置组。

这些配置位于 `meta`，不会影响 `data` 中逐帧数组长度。`replay_zarr.py` 会按 episode 编号读取 `start_bias` 用于复位后的开局偏置移动，并读取 `gripper_range` 配置 Env 的夹爪原始行程、读取 `gripper_mode` 选择二值或连续回放。



## 数据转换

使用 `scripts/data/convert_to_lerobot.py` 将 Zarr 数据转换为 LeRobot 数据集。在仓库根目录启动：

```bash
python scripts/data/convert_to_lerobot.py \
    --input datasets/demo.zarr \
    --output lerobot_datasets/demo
```

`--input`（`-i`）和 `--output`（`-o`）分别指定 Zarr 输入和 LeRobot 输出路径，均为必填参数。两者不能相同或相互包含。脚本以只读方式打开 Zarr，依靠 `meta/episode_ends` 分轮；缺失时报告错误退出，不重建索引。

### 交互流程与配置

脚本先读取并显示 Zarr 概览，包括输入路径、总帧数、episode 数量及每轮帧数、根与 `data` / `meta` 的属性，以及数组的路径、shape 和 dtype。逐帧数据不在概览中逐一打印。

1. **查看单轮 meta**：菜单默认选择“继续”。输入 `1` 后填写从 `0` 开始的 episode 编号，显示该轮 `meta/episode_config/episode_XXXXXX` 的属性；随后再次询问是否查看。对应配置缺失时提示该轮没有 meta，并继续询问；编号超出范围时报告错误并退出。
2. **填写数据集配置**：按顺序输入 repo ID、fps、robot type 和 task。输入提示显示默认值，有默认值时直接回车即可使用。

   | 配置 | 默认值 | 说明 |
   | --- | --- | --- |
   | repo ID | 无，必填 | LeRobot 数据集标识；验证时使用相同的值 |
   | fps | `30` | 输出数据集帧率，须输入正整数 |
   | robot type | `xarm6` | 写入数据集元数据的机器人类型 |
   | task | 无，必填 | 非空任务描述，传入每一帧 |

3. **选择轮次**：数字菜单默认选择全部 episode；也可选择前 N 轮，再输入正整数 N。N 不能大于数据集的 episode 总数。
4. **选择字段**：菜单列出源数据中可选字段和对应的输出字段。一次输入多个编号，使用空格分隔，例如 `1 2 3 4`；具体编号以当前菜单为准。直接回车表示空选择，脚本会提示并要求重新选择。选择没有映射的字段时，会指出字段并提示自行补充规则；编号无效、重复或组合字段不完整等情况提示选择不合理，均返回字段选择。`episode` 是分轮索引，不在转换字段菜单中。
5. **确认输出和配置**：输出目录已存在时，选择覆盖或退出，默认退出。随后脚本显示路径、数据集配置、轮数和帧数、选择的映射、未转换字段及覆盖决定。最后选择开始或取消，默认取消；只有选覆盖并最终确认开始后，才删除原输出目录。
6. **执行转换**：脚本依据所选字段创建 LeRobot 数据集，按 episode 批量读取数据、逐帧转换并写入，每轮保存一次，最后完成元数据写入并显示输出路径、轮数、帧数和耗时。图像以图片形式保存，当前创建配置为 `use_videos=False`，图像写入线程数为 `4`。

数字菜单输入选项编号。除字段选择需要重选、所选 episode 没有 meta 时可继续查看外，输入或转换出错时脚本报告问题并退出。转换失败后可能留下已经创建的输出目录。

### 字段映射

菜单中的两项组合字段须整体选择；其余已映射字段可分别选择。传感器字段仅在源数据存在且用户选中时写入。

| Zarr 字段 | LeRobot 字段 | 转换 |
| --- | --- | --- |
| `rgb_fix` | `observation.image` | CHW 转 HWC，使用固定相机自身的图像尺寸 |
| `rgb_arm` | `observation.wrist_image` | CHW 转 HWC，使用腕部相机自身的图像尺寸 |
| `pos` + `gripper_state` | `observation.state` | 拼接为 7 维 `float32` |
| `action` + `gripper_action` | `action` | 拼接为 7 维 `float32` |
| `force` | `observation.force` | 6 维 `float32` |
| `coinft_left` | `observation.coinft_left` | 6 维 `float32` |
| `coinft_right` | `observation.coinft_right` | 6 维 `float32` |

输入的 task 会传入每一帧。`data/episode` 用作分轮信息，不作为普通字段选择。`gripper_raw_position`、`gripper_raw_action`、深度和其他未配置映射的字段不会自动转换；选中时脚本提示自行补充映射规则并重新选择。逐 episode 的 `gripper_mode`、`gripper_range` 等 meta 供查看，不复制到 LeRobot。选择 state/action 组合时，归一化夹爪值保持采集值，不进行二值化。

转换完成后可用 `python scripts/data/verify_lerobot.py --path lerobot_datasets/demo --repo-id demo` 检查结果；repo ID 与转换时输入的值保持一致。
