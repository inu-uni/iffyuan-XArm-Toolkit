# 模型部署

> 这篇解决的问题：怎么把训练好的 Pi0.5 VLA 模型跑到 XArm6 真机上。

## 部署架构

部署采用 **Server-Client 分离架构**，GPU 推理和机器人控制分别运行在两台机器上，通过 WebSocket + msgpack 通信：

```
┌──────────────────────────────────────┐     ┌──────────────────────────────────────┐
│          GPU 机器 (Server)            │     │         机器人机器 (Client)            │
│                                      │     │                                      │
│  openpi config (.py)                 │     │  XArmEnv (delta_eef)                 │
│       ↓                              │     │  RealsenseEnv × 2 (D435i + L515)     │
│  Pi05XArmPolicy                      │     │       ↓                              │
│    · load_config_from_file()         │     │  build_state():                      │
│    · policy.infer(obs) → actions     │     │    goal_pos(6) + gripper(按模式)     │
│       ↓                              │     │       ↓                              │
│  VLAServer (WebSocket :10093)  ◄─────┼─────┤  VLAClient ──→ predict()            │
│    · 接收 images + state + prompt    │     │       ↓                              │
│    · 返回 actions (chunk_size, 7)    │     │  XArmDeployer.run():                 │
│                                      │     │    actions[0][:6] → env.step()       │
│  scripts/openpi_server.py            │     │    actions[0][6]  → gripper 按模式执行│
└──────────────────────────────────────┘     │                                      │
                                             │  scripts/deploy_vla.py               │
                                             └──────────────────────────────────────┘
```

## 数据格式约定

部署时的数据格式与采集/训练完全一致：

| 字段 | 格式 | 说明 |
|------|------|------|
| `observation/image` | HWC uint8 | 固定相机 (L515) RGB |
| `observation/wrist_image` | HWC uint8 | 臂上相机 (D435i) RGB |
| `observation/state` | float32 (7,) | `goal_pos(6) + gripper(1)`；第七维按 `gripper_mode` 编码 |
| `prompt` | str | 语言指令 |
| **输出** actions | float32 (chunk_size, 7) | `delta_eef(6) + gripper(1)` |

**State 细节：**
- `goal_pos`: commanded 目标位姿 `[x, y, z, roll, pitch, yaw]`，与 Collector 存的 `pos` 一致
- `gripper`: 归一化夹爪状态。`binary` 模式按 `<=0.5` 编为闭合 `0`、`>0.5` 编为张开 `1`；`continuous` 模式保留 `0～1` 连续值，与 Collector 的 `gripper_state` 对应

**Action 细节：**
- 前 6 维: delta EEF `[dx, dy, dz, dr, dp, dy]`
- 第 7 维: 归一化夹爪动作。`binary` 模式按 0.5 阈值映射为 `0/1`；`continuous` 模式将模型输出直接传给 Env，由 Env 映射到配置的 SDK 原始行程

state 和 action 必须使用与训练数据相同的模式。WebSocket/msgpack 层传递 float32 数组，不会改变夹爪值；模式由机器人端部署入口控制。

## 前置准备

### Config 文件

openpi 训练时会产生一个 config Python 文件，其中必须定义 `build_config()` 函数，返回 openpi `TrainConfig`。部署时直接指定该文件路径。

示例 config 文件结构：

```python
# pi05_xarm_v2_stage1.py
def build_config():
    """返回 openpi TrainConfig."""
    from openpi.training.config import TrainConfig
    # ... 构建并返回 config
    return config
```

例如在本例子中，这个文件位于:`/home/ubuntu/openpi/pi05_xarm_v2_stage1.py`

### Checkpoint

训练完成后的 checkpoint 目录，例如：

```
/home/ubuntu/models/xarm6_act_pick2_pi05
```

## 启动步骤

### Step 1: 启动 GPU 端推理服务

在 GPU 机器上运行：

```bash
python scripts/openpi_server.py \
    --config-file /home/ubuntu/demo/openpi05/config.py \
    --ckpt-dir /home/ubuntu/models/xarm6_act_pick2_pi05 \
    --port 10093
```

**参数说明：**

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `--config-file` | ✅ | — | openpi config Python 文件路径 |
| `--ckpt-dir` | ✅ | — | checkpoint 目录路径 |
| `--port` | | 10093 | WebSocket 服务端口 |
| `--host` | | 0.0.0.0 | 绑定地址 |
| `--idle-timeout` | | 0 | 连接空闲超时秒数（0=不超时） |

启动成功后会看到：

```
[INFO] Loaded config from: /path/to/pi05_xarm_v2_stage1.py
[INFO] Using local checkpoint: /path/to/checkpoint/29999
[INFO] Creating trained policy ...
[INFO] Pi0.5 XArm policy ready.
[INFO] Starting OpenPI server on 0.0.0.0:10093
```

### Step 2: 启动机器人端部署

在机器人机器上运行（确保 XArm 和相机已连接）：

```bash
python scripts/deploy_vla.py \
    --server-host <GPU机器IP> \
    --instruction "pick up the orange toy and place it to the plate" \
    --hz 10 \
    --speed 100
```

**参数说明：**

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `--server-host` | | localhost | GPU 端 server IP |
| `--server-port` | | 10093 | GPU 端 server 端口 |
| `--instruction` | ✅ | — | 语言指令 |
| `--ip` | | 192.168.31.232 | XArm 控制器 IP |
| `--action-mode` | | delta_eef | 动作模式 |
| `--max-steps` | | 500 | 最大执行步数 |
| `--hz` | | 10.0 | 控制频率 (Hz) |
| `--speed` | | 100 | EEF 模式笛卡尔速度参数，有效范围 `(0, 2000]`；仅 `delta_eef` 和 `absolute_eef` 模式使用 |
| `--use-force` | | false | 是否开启力控 |
| `--gripper-range MIN MAX` | | `0 840` | SDK 原始闭合、张开位置，传给 XArmDeployer 和 Env |
| `--gripper-mode` | | `binary` | `binary` 保留二值 state/action 处理；`continuous` 保留归一化连续 state/action |
| `--debug` | | false | 输出每一步服务器动作（含夹爪输入和命令）及动作执行前的末端反馈位姿 |

**Debug 控制条件：**

- 默认不传 `--debug`，动作和末端位姿调试日志关闭。传入 `--debug` 后两类日志同时开启。
- 动作日志包含本步服务器动作、夹爪输入和命令；末端位姿日志记录动作执行前的反馈位姿 `obs["cart_pos"]`。
- 每隔 10 步输出的 `elapsed`、位置和夹爪状态属于运行状态日志，不受 debug 开关影响。

调试选项示例：

```bash
python scripts/deploy_vla.py \
    --server-host <GPU机器IP> \
    --instruction "pick up the orange toy and place it to the plate" \
    --debug
```

连续夹爪模型需要在机器人端指定 `--gripper-mode continuous`，例如：

```bash
python scripts/deploy_vla.py \
    --server-host <GPU机器IP> \
    --instruction "pick up the orange toy and place it to the plate" \
    --gripper-mode continuous
```

单机本地推理入口 `scripts/deploy_local.py` 也接受相同的 `--gripper-mode binary|continuous` 参数，默认 `binary`。state 和 action 的处理方式与远程部署相同，例如：

```bash
python scripts/deploy_local.py \
    --config-file /path/to/pi05_xarm_v2_stage1.py \
    --ckpt-dir /path/to/checkpoint \
    --gripper-mode continuous
```

## Python API 用法

如果需要在代码中直接调用（不走 scripts 入口）：

### Server 端

```python
from xarm_toolkit.deploy.openpi_server import Pi05XArmPolicy
from xarm_toolkit.deploy.server import VLAServer

policy = Pi05XArmPolicy(
    config_file="/path/to/pi05_xarm_v2_stage1.py",
    ckpt_dir="/path/to/checkpoint/29999",
)

server = VLAServer(
    policy=policy,
    port=10093,
    metadata={
        "model": "pi0.5",
        "action_format": "delta_eef(6)+gripper(1)",
    },
)
server.run()  # 阻塞
```

### Client 端

```python
from xarm_toolkit.deploy.robot_deploy import XArmDeployer

deployer = XArmDeployer(
    env=env,
    cam_arm=cam_arm,
    cam_fix=cam_fix,
    server_host="192.168.1.100",
    server_port=10093,
    instruction="pick up the orange toy and place it to the plate",
    action_mode="delta_eef",
    gripper_mode="continuous",
    max_steps=300,
    hz=10.0,
)
deployer.run()  # 阻塞，Ctrl+C 退出
```

### 单独使用 VLAClient（自定义控制循环）

```python
from xarm_toolkit.deploy.client import VLAClient
import numpy as np

client = VLAClient(host="192.168.1.100", port=10093)

# 发送推理请求
result = client.predict(
    images=[rgb_arm, rgb_fix],          # list[np.ndarray], HWC uint8
    instruction="pick up the cup",
    state=np.array([470, 0, 530, 3.14, 0, -1.57, 1], dtype=np.float32),
)

actions = result["actions"]  # (chunk_size, 7)
print(actions.shape)         # e.g. (50, 7)

client.close()
```

## 部署控制循环详解

`XArmDeployer.run()` 的每一步执行：

```
1. 相机采集 rgb_arm (wrist), rgb_fix (base)
2. 读取 obs → build_state(): goal_pos(6) + 按 gripper_mode 编码的夹爪值
3. VLAClient.predict() → server 推理 → actions (chunk_size, 7)
4. 取 actions[0]:
   - [:6] → env.step(action=delta_eef)
   - [6]  → binary: 按 0.5 阈值映射为 0/1；continuous: 原值传给 Env
5. Rate control: sleep 补齐到目标频率
6. 循环直到 max_steps 或 Ctrl+C
```

## 夹爪范围配置接口

| 调用入口 | 配置方式 | 默认值 |
| --- | --- | --- |
| `scripts/deploy_vla.py` | `--gripper-range MIN MAX` | `0 840` |
| `scripts/deploy_local.py` | `--gripper-range MIN MAX` | `0 840` |
| `scripts/deploy_diffusion.py` | YAML/JSON 配置键 `gripper_range` | `[0, 840]` |
| `XArmDeployer(...)` | `gripper_range=(MIN, MAX)` | `(0, 840)` |

VLA 夹爪编码模式由机器人端部署入口设置：

| 调用入口 | 配置方式 | 默认值 |
| --- | --- | --- |
| `scripts/deploy_vla.py` | `--gripper-mode binary|continuous` | `binary` |
| `scripts/deploy_local.py` | `--gripper-mode binary|continuous` | `binary` |
| `XArmDeployer(...)` | `gripper_mode="binary"` 或 `"continuous"` | `binary` |

```python
deployer = XArmDeployer(gripper_range=(200, 700))
```

Diffusion 配置：

```yaml
gripper_range: [200, 700]
```

`deploy_vla.py` 和 `deploy_local.py` 在 `binary` 模式下向 Env 发送 `0/1`，并按相同阈值编码反馈状态；在 `continuous` 模式下保留归一化 state/action 值。`deploy_diffusion.py` 当前仍固定使用二值夹爪处理，不支持连续模式。
